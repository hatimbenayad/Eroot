# Eroot Risk Register (Inception)

| ID | Risk | Likelihood | Impact | Mitigation | Owner Unit |
|---|---|---|---|---|---|
| RSK-01 | **Supabase Free tier Realtime limits** (~200 concurrent connections, message-rate caps) hit during a 100-player game if every player triggers presence/broadcast storms. | Medium | High | Keep max 1 Realtime channel per client (`game:<id>`); broadcast aggregate answer counts on a throttled interval (e.g., max 2/sec) rather than per-submission full-state rebroadcasts; validate with 100-player load test. | U4, U10 |
| RSK-02 | **Correct answer leakage** to player devices before `question_reveal` via API responses, Supabase RLS, or Realtime payloads. | Medium | Critical | Store authoritative `quiz_snapshot` in a private table/column locked by RLS (`auth.uid() = host_id`); players receive sanitized slide payloads (`stripAnswerKeys()`) via `/api/games/*` and Realtime channels until state transitions to `question_reveal`. | U4 |
| RSK-03 | **Timer drift & network latency unfairness** between host screen, server, and mobile devices. | High | Medium | Stamp `question_started_at` on the server; calculate `response_ms = clamp(serverNow - questionStartedAt, 0, questionMs)`; allow a small 500 ms post-close submission grace window for in-flight HTTP requests; sync player countdown via server offset. | U4 |
| RSK-04 | **Vercel cold starts** delaying `/api/games/*/answer` when 100 players submit simultaneously in the first 2 seconds. | Medium | Medium | Keep API handlers lightweight (minimal imports, Zod + Supabase REST/RPC directly); use Postgres RPC for atomic answer insert + score calculation to avoid multi-roundtrip handler delays. | U1, U4 |
| RSK-05 | **PIN brute-force & spam joins** exhausting game slots (`max_players = 100`) or guessing active 6–7 digit PINs. | Medium | High | Use 7-digit cryptographically random PINs, enforce IP/session rate limiting on `/api/games/join` and PIN lookup, return uniform errors, and support host kick + friendly nicknames mode. | U4, U10 |
| RSK-06 | **Creator edits corrupting active games or historical reports.** | High (if unmitigated) | High | Deep-copy the validated quiz structure into `games.quiz_snapshot` upon lobby/challenge creation so live play and reports never read mutable `slides`. | U4 |
| RSK-07 | **Spreadsheet import injection / malformed files** (`.csv` / `.xlsx` formula injection, huge files, unsupported types). | Medium | Medium | Enforce strict file size/row limits, parse client/server-side with sanitized string extraction (escaping leading `=`, `+`, `-`, `@` on CSV export too), and validate every row against Zod schemas with preview feedback before insert. | U6, U7 |
| RSK-08 | **Pin answer / Drop pin coordinate mismatch** across varying aspect ratios between Creator desktop and Player mobile screens. | Medium | Medium | Store and submit normalized `(x, y)` coordinates in `[0, 1]` relative to the rendered image box (`object-contain` wrapper locked to natural image aspect ratio), never pixel coordinates. | U9 |
| RSK-09 | **Yellow/amber answer tile contrast failure** under WCAG AA (`4.5:1`). | High (if white text used) | Medium | Use dark slate ink (`#0f172a`) on bright yellow/amber surfaces (or sufficiently dark `#a16207` background if white text), validated via contrast tokens in U1 and `axe` checks in U10. | U1, U10 |
| RSK-10 | **Scope creep / accidental AI or paywall references.** | Low | Medium | Keep explicit checks in unit specs and code reviews forbidding AI prompts/endpoints/Upgrade UI; restrict themed arcade modes strictly to `Future`. | All |
